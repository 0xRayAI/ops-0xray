Definition

What is AI Fleet OPS

Yes. AI Fleet OPS is the production discipline that keeps a multi-agent system shipping after the demo. The outcome is a job that survives a context reset, a release a human can audit, and a public post that waits for its own go. You get it by naming roles, using one queue, and writing the procedure on disk.

What breaks when agents only share a chat?

Teams add agents the way they add browser tabs. Each session starts blank. Two agents edit the same files. The status report is a chat line that says the work is finished. A week later nobody can point to the owner, the acceptance check, or why a public post went out.

Agent reliability fails in a specific place. The context window closes, and the job lived only inside that window. The next session invents a new plan. Observability fails in the same place: if the queue has no ticket, there is nothing to watch.

What has to be true at the same time?

AI Fleet OPS is the operating model for a multi-agent system that has to ship. Four parts stay true together.

Roles

Someone implements. Someone reviews. Someone coordinates the queue. A human owner holds money, credentials, deletes, publishing, and taste. The role is the assignment. It is not the model brand and it is not a person's chat handle.

One queue

Every task is a ticket, an issue or a pull request, with an owner, a stage, and a state. Agent orchestration means the queue and the roles still agree after the session ends. The control plane guide is the detail.

A procedure on disk

After a restart the role reads the written procedure and a one-line session ticket, then continues the same job. Notes hold the long body. A recollection inside the model is not the procedure. Standing that up is the house path.

Two gates that stay separate

A release gate decides whether code ships. A go-to-market gate decides whether anyone says so in public. The eval is the acceptance written on the brief before the run. The reviewer compares the result to that acceptance. Human-in-the-loop means the reviewer records the verdict, and the human owner still decides spend, production, and anything public. Posts wait on that second gate.

On this fleet the kit an agent runs with is the suit, a named role is a seat, and the roster under one procedure is the fleet. The short names sit in the glossary.

How do you place the team?

  1. Name the roles you actually need. Implementer, reviewer, coordinator, and the human owner. Write one line on what each may do without asking.
  2. Write the job in one sentence and point at the ticket that holds it. If the sentence has no ticket, the team does not have the job yet.
  3. Pick one queue and one procedure file. Tell every role where they are. Retire the other board and the other doc.
  4. Write acceptance before the run. That paragraph is the eval. Review will score the diff against it.
  5. Split release from announcement. A recorded PASS ships code. Public language waits for the owner's go.
  6. Set a weekly compute line before you add the second agent. New runs stop when weekly spend reaches the hold line.

Where does a new fleet usually break?

  • Chat as the system of record. The session ends and the owner, the acceptance, and the next cut leave with it.
  • One shared prompt called a team. Roles are unnamed, so two agents take the same task and neither owns the result.
  • Green build called done. Continuous integration passed. There is still no reviewer receipt and no live proof.
  • Announcement from the build channel. A demo worked, a post went out, and the public lane never had an owner or a go.

What else do operators ask?

How is a multi-agent fleet different from several agents in one chat?

A fleet has named roles, one queue, and a ticket for each task. A chat can brief a role. The ticket is what owns, resumes, and proves the work.

What does agent reliability mean here?

The same job is still there after a restart. Release depends on a recorded review, not on the agent saying it is done. You can see the stage and the owner on the queue.

What has to exist before the first ship?

A fastened operating kit, a house file that names the owner and the roles, one queue, and a first ticket whose brief names who does the work and who answers for it.

Where does human judgment sit?

The human owner decides money, credentials, deletes, publishing, and taste. A reviewer role records PASS or FIX on the change. Those are different decisions.
